# 关于这次科技树实验

[返回科技树](README.md) · [图谱 JSON](../data/robotics-tree.json ':ignore')

这个原型探索一个问题：机器人学习地图能否既方便人浏览，又足够明确，让 AI 智能体能够使用？它是用于讨论的小规模样例，不是完整课程，也不是对任何人能力的评定。

## 如何阅读地图

理论与工程视角提供了同一张图谱的两个入口，两者可以重叠。共享节点同时属于两个视角。卡片分布在基础、建模、自主能力与系统集成四个浏览阶段中；这些阶段是编辑者设定的展示坐标，不是固定的学习时间表或必须逐级通过的关卡。

视图借鉴《文明》科技树，用卡片和连线展示关系。机器人知识更适合表示为图：一个主题可以有多个前置条件、支持多个项目，也可以在不同深度反复学习。选择节点后，可以查看学习成果、建议的验证材料及相关关系。验证材料描述的是一种展示所学的方法，并不表示学习者已经完成它。

样例中的所有连线都是提案。`prerequisite` 表示“先学习起点，再学习终点”；`application` 表示“终点应用起点的知识”。每条边都有理由。这些关系和四阶段分组都是待讨论的假设，不是原文明确给出的依赖关系。

## 一份图谱，两类使用者

[robotics-tree.json](../data/robotics-tree.json ':ignore') 是图谱的唯一权威数据源。可视化与智能体导出应读取同一份文件。中英文 Markdown 提供说明，不各自维护一套图谱数据。

`0.1.0` 版数据约定包括：

- `schemaVersion` 和 `status: "brainstorm"` 标明格式与成熟度；`sources` 保存来源信息。
- 节点包含稳定的 `id`，双语 `title`、`summary`、`outcomes` 和 `evidence`，以及 `tracks`（`theory`、`engineering` 或两者）、`topics` 和 `sourceIds`。`provenance` 区分改编内容 `adapted` 与新增提案 `proposal`。
- `stage` 和 `slot` 只用于展示。智能体不能根据卡片位置推断依赖关系。
- 边包含 `id`、`from`、`to`、`type`、双语 `rationale` 和 `provenance: "proposal"`。应遵循明确的连线，而不是相似标题或相邻位置。

计划提供的智能体入口包括完整图谱下载，以及包含所选节点全部直接和间接前置节点的上下文导出。智能体在总结或建议学习路径时，应保留标识符、边的含义、内容性质及来源。不能把应用关系默认为前置关系。建议路径仍需学习者审阅。

## 来源与边界

[Issue #1](https://github.com/miao-org/white-paper/issues/1) 提出了这次实验的讨论背景。学习内容以[《机器人工程师学习计划》](https://github.com/ShuoYangRobotics/personal-ai-space/blob/main/zhihu-writing/articles/2016-09-08_机器人工程师学习计划.md)为种子，[原文于 2016 年 9 月 8 日发表于知乎](https://zhuanlan.zhihu.com/p/22266788)。样例借鉴了它对物理世界交互、理论与实践并行、反复学习基础以及系统工程能力的重视。

原文按六个学年展开；这里的四阶段是为了紧凑展示而做的改编。原文中带有年代背景的工具、硬件建议和研究前沿判断，尚未核验或更新为当前课程。样例提出的学习成果、验证材料和依赖关系都需要审阅。《文明》的科技树用于参考浏览方式，不作为知识内容的来源。

## 下一轮讨论的问题

1. 一张卡片应该表示概念、实践能力，还是项目？何时需要把它们分成不同节点类型？
2. 哪些前置条件是必要的，哪些只是有帮助？哪里可以存在替代路径？
3. 什么验证材料能帮助智能体规划下一步：代码、仿真、测量结果，还是解释说明？
4. 理论／工程视角是否最方便浏览？下一种视图是否应从“搭建移动机器人”这样的目标出发？

## 预览与检查

在仓库根目录运行：

```sh
python3 -m http.server 8000 --directory docs
python3 scripts/check_docs.py
python3 scripts/check_tree.py
```

打开[本地预览](http://localhost:8000)。检查脚本验证文档和图谱结构，不能证明所提学习关系在教育上成立。
